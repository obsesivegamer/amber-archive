Amber

how it works

Paste a public URL. Amber opens it in a real Chromium browser, waits for the page to render, then stores three things:

  • Webpage — the HTML after JavaScript has run, with scripts and forms stripped. Images and CSS are saved locally so the copy still works if the original site goes away.
  • Screenshot — a graphical copy of what the page looked like.
  • Text — a readable article extract (title, byline, body) for news and blogs.

Each snapshot gets a short id such as /K7mQp. That record is not edited later.

Amber loads the page as a first-time visitor (fresh browser, no cookies). If that visit only gets a metered teaser, it retries in a new browser from a Google or X referrer — the same free-read path those publishers already grant. Overlays that hide text already on the page are removed so the snapshot shows what was actually loaded. Login-only pages stay incomplete; import a saved HTML file to keep those.

Only http(s) URLs on the public internet are accepted. Private/local addresses are blocked. Tracker and ad hosts are skipped during capture so snapshots stay smaller and quieter.

This is a self-hosted personal archive. Snapshots live in data/snaps/ on the machine that runs Amber.
